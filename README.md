# Survey QA

Внутренний веб-сервис для автоматической проверки тестовой ссылки по Word-анкете.

Пользователь загружает `.docx`, вставляет тестовую ссылку и получает отчёт о расхождениях. Первая версия поддерживает EnjoySurvey и архитектурно готова к добавлению других платформ.

## Что уже реализовано

- извлечение вопросов из абзацев и таблиц Word;
- распознавание кодов вида `S1`, `S2b`, `B10.44`, `B21_1`, `C16_1`;
- одиночные, множественные, открытые, шкальные и матричные вопросы;
- варианты ответов, коды, исключающие и закреплённые варианты;
- условия `=`, `!=`, `≠`, диапазоны и списки кодов;
- формулировки «задать», «показывать», «продолжить», «закончить»;
- ротация вариантов, строк, столбцов и концептов;
- чтение структуры EnjoySurvey через тестовую панель быстрого перехода;
- сравнение вопросов, формулировок, типов, вариантов и порядка;
- генерация положительных и отрицательных сценариев для условий показа;
- отдельная проверка каждой части составного условия `И` / `ИЛИ`;
- независимые браузерные прохождения с Playwright;
- автоматическое заполнение обычных вопросов, открытых полей, шкал и каждой строки матрицы;
- русскоязычный веб-интерфейс и JSON-отчёт;
- удаление загруженного Word после завершения проверки.

Квоты намеренно не проверяются. Сервис сообщает, что вопрос появился или не появился, но не пытается диагностировать причину ошибки в настройках платформы.

Важно: сервису нужна активная тестовая ссылка, которая открывается без входа в личный кабинет. Перенаправление на страницу входа определяется как истёкшая, закрытая или защищённая ссылка.

## Структура проекта

```text
app/
  docx_parser.py       разбор Word
  logic_parser.py      условия, переходы и ротации
  planner.py           генерация маршрутов
  comparator.py        сравнение Word и ссылки
  pipeline.py          полный процесс проверки
  platforms/
    enjoysurvey.py     модуль EnjoySurvey
  static/              веб-интерфейс
tests/                 автоматические тесты
scripts/               служебные команды
Dockerfile             контейнер с Chromium
render.yaml            развёртывание на Render
```

Подробности находятся в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [docs/SUPPORTED_WORD_PATTERNS.md](docs/SUPPORTED_WORD_PATTERNS.md).

## Локальный запуск

Требуется Python 3.12.

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m playwright install --with-deps chromium
$env:APP_ACCESS_USERNAME="surveyqa"
$env:APP_ACCESS_PASSWORD="ваш-пароль"
$env:MAX_LOGIC_SCENARIOS="80"
uvicorn app.main:app --reload
```

macOS/Linux:

```bash
source .venv/bin/activate
pip install -r requirements.txt
python -m playwright install --with-deps chromium
export APP_ACCESS_USERNAME="surveyqa"
export APP_ACCESS_PASSWORD="ваш-пароль"
export MAX_LOGIC_SCENARIOS="80"
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000`.

## Проверка парсера на локальных анкетах

Исходные анкеты не должны попадать в GitHub. Они исключены через `.gitignore`.

```bash
python scripts/parse_samples.py "C:\путь\к\папке\с\анкетами"
```

JSON появится в `reports/parsed/`.

## Развёртывание на GitHub и Render

1. Создайте пустой репозиторий GitHub.
2. Загрузите в него содержимое папки `survey-qa`.
3. В Render выберите **New Blueprint** и подключите репозиторий.
4. Render прочитает `render.yaml` и создаст Docker Web Service.
5. Введите секретное значение `APP_ACCESS_PASSWORD`. Логин по умолчанию: `surveyqa`.
6. После сборки откройте выданный адрес `onrender.com`.

Для Chromium используется Docker, поэтому системные зависимости устанавливаются автоматически.

## Ограничения текущего MVP

- в памяти хранится только текущая история запусков; после перезапуска Render старые отчёты исчезнут;
- одновременно выполняется одна проверка, чтобы несколько Chromium-процессов не исчерпали память;
- по умолчанию запускается до 80 логических сценариев; если их больше, это явно отражается в отчёте, а лимит меняется через `MAX_LOGIC_SCENARIOS`;
- автоматические ветвления требуют, чтобы тестовая ссылка позволяла начинать независимые сессии;
- неизвестная или неоднозначная инструкция Word попадает в предупреждения;
- составные условия покрываются по каждому атому, но глубоко вложенные выражения вида `(A И B) ИЛИ (C И D)` пока требуют ручного уточнения;
- ротация определяется статистически по трём независимым сессиям, поэтому редко возможно случайное совпадение порядка;
- повторяющиеся коды вопросов в циклах и концептах помечаются предупреждением и требуют внимательной проверки отчёта;
- поддерживается EnjoySurvey; следующая платформа добавляется отдельным модулем в `app/platforms/`;
- скриншоты ошибок и HTML/Excel-экспорт запланированы следующим этапом.

## Конфиденциальность

- не загружайте рабочие анкеты в GitHub;
- установите `APP_ACCESS_PASSWORD`;
- не выводите содержимое анкет в логи Render;
- текущая реализация удаляет временный `.docx` сразу после обработки;
- для корпоративного размещения тот же Docker-образ можно запустить на внутреннем сервере.
